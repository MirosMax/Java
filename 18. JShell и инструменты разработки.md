## JShell

REPL-среда для Java (Java 9+). Позволяет исполнять фрагменты кода без компиляции и класса с `main` — удобно для экспериментов и изучения (см. [[01. Основы языка Java#Метод main|структуру программы]]).

```text
jshell> int x = 5;
x ==> 5

jshell> x * x;
$2 ==> 25

jshell> var list = new ArrayList<String>();
list ==> []
```

Особенности:

- Каждый фрагмент (сниппет) выполняется немедленно; результат печатается.
- Имя файла/класса не нужно — код вводится интерактивно.
- Вводится в строку с `Tab` для автодополнения.
- Выход — `/exit`.

## Команды JShell

Команды начинаются со слэша:

```text
/help          справка
/list          список введённых сниппетов (с идентификаторами)
/vars          объявленные переменные
/methods       объявленные методы
/types         объявленные классы/интерфейсы
/imports       импортированные пакеты
/open file     выполнить сниппеты из файла
/save file     сохранить сниппеты в файл
/edit          открыть редактор сниппетов
/reset         сбросить состояние сессии
/reload        перезапустить сессию с сохранением сниппетов
/env           состояние окружения: imports, vars, методы
/history       история ввода
/set           настройки: /set editor, /set feedback, /set start
/exit          выход
```

Обращение к сниппетам по идентификаторам:

```text
jshell> /list
   1 : int x = 5;
   2 : x * x;
   3 : var list = new ArrayList<String>();

jshell> /list 2      # показать конкретный сниппет
/edit 2              # отредактировать
/drop 2              # удалить сниппет
```

Управление автозапуском и форматом вывода:

```text
/set start myscript.jsh   # сниппеты, выполняемые при старте JShell
/set feedback verbose     # подробный вывод типов и результатов
/set editor notepad       # внешний редактор для /edit
```

## Сниппеты и переменные

### Методы и классы

В JShell можно определять методы, классы и интерфейсы, переиспользуя их дальше:

```java
jshell> int square(int n) { return n * n; }
|  created method square(int)

jshell> square(7)
$5 ==> 49
```

### Исключения и импорт

```java
jshell> import java.time.*;

jshell> LocalDate.now()
$6 ==> 2026-08-21
```

Исключения печатаются сразу, не прерывая сессию:

```java
jshell> int r = 10 / 0;
|  java.lang.ArithmeticException: / by zero
|      at (#7:1)
```

### Переопределение и встроенные переменные

Сниппет можно переопределить — новое определение заменяет старое:

```java
jshell> int x = 1;
x ==> 1

jshell> int x = 100;      // переопределение
x ==> 100
```

Результаты выражений попадают во встроенные переменные `$N`, к ним можно обращаться:

```java
jshell> 6 * 7
$8 ==> 42

jshell> $8 + 1
$9 ==> 43
```

Встроенные импорты по умолчанию: `java.lang.*`, `java.util.*`, `java.io.*`, `java.math.*` и др.

### Сценарии JShell (файлы `.jsh`)

Сниппеты можно сохранять в скрипт-файл и выполнять:

```java
// demo.jsh
int base = 10;
int doubleIt(int n) { return n * 2; }
System.out.println(doubleIt(base));

// выполнение
jshell> /open demo.jsh
```
```text
jshell /open demo.jsh     # из командной строки: загрузить и выполнить скрипт
```

## Запуск однофайловых программ

С Java 11 программу из одного `.java`-файла можно запустить напрямую — компиляция и запуск выполняются в одном шаге (source-file mode):

```text
java Hello.java         # компилирует и запускает Hello.java
```

- Обязательно расширение `.java` и `main` в файле.
- Доступны внешние библиотеки: `java -cp lib.jar Hello.java`.
- Shebang для Unix-скриптов: первая строка `#!/usr/bin/env java --source 21`.

Точка входа может быть в любом классе файла, а не только в публичном (см. [[01. Основы языка Java#Метод main|метод main]]).

Опции запуска:

```text
java Hello.java arg1 arg2      # аргументы программы (после имени файла)
java -cp lib.jar App.java      # внешние библиотеки
java --class-path out App.java # то же, длинная форма
java --source 21 Hello.java    # явная версия Java (для shebang-скриптов)
```

Ограничения source-file mode:

- Работает только для программы из **одного файла**; многофайловые проекты — через `javac`/сборщик (см. [[15. JVM, память и профессиональная разработка#Сборка проектов|сборку]]).
- Файл запускается как скрипт: компилируется в память, `.class` не остаётся на диске (кроме опции `-d`).
- Подходит для прототипов, утилит и учебных примеров; для продакшена — полноценная сборка.

Shebang-скрипт для Unix:

```java
#!/usr/bin/env java --source 21
public class Hello {
    public static void main(String[] args) {
        System.out.println("Привет из скрипта");
    }
}
```

Файл с правами на выполнение запускается напрямую: `./Hello`.

## Утилиты JDK

Инструменты командной строки из JDK (см. [[01. Основы языка Java#JDK, JRE и JVM|JDK]]):

```text
javac          компилятор: Hello.java -> Hello.class
java           запуск: байт-код или .java (однофайловый режим)
jar            создание/чтение JAR-архивов (см. [[15. JVM, память и профессиональная разработка#JAR|JAR]])
javadoc        генерация документации (см. [[15. JVM, память и профессиональная разработка#Документирование Javadoc|Javadoc]])
jlink          сборка компактного рантайма (см. [[15. JVM, память и профессиональная разработка#jlink и jpackage|jlink]])
jpackage       нативные установщики
jshell         интерактивная среда
```

Диагностика и анализ:

```text
javap -c Class   # дизассемблер байт-кода (см. [[01. Основы языка Java#Байткод|байт-код]])
javap -p Class   # показать private-члены
javap -v Class   # подробно (константный пул, сигнатуры)

jdeps -s jar     # зависимости модулей (см. [[15. JVM, память и профессиональная разработка#Модульная система|модули]])
jdeps --print-module-deps jar   # какие модули нужны для jlink

jcmd <pid> help  # диагностика JVM: GC, threads, heap
jps             # список Java-процессов
jstack <pid>    # дамп потоков (см. [[14. Многопоточность и конкурентность|потоки]])
jmap -heap <pid> # состояние кучи (см. [[15. JVM, память и профессиональная разработка#Память JVM|память]])
jstat -gc <pid> # статистика GC в реальном времени (см. [[15. JVM, память и профессиональная разработка#Garbage Collector|GC]])
jfr            # запись Flight Recorder (профилирование)
```

Прочее:

```text
keytool         # управление сертификатами и ключами (TLS)
serialver -show # серийная версия класса (см. [[12. Ввод-вывод, файлы и сериализация#serialVersionUID|serialVersionUID]])
javac -d out src/App.java   # компиляция с каталогом классов
java -Xlog:gc  # логирование сборок мусора (см. [[15. JVM, память и профессиональная разработка#Garbage Collector|GC]])
```

### jwebserver (Java 18+)

Простой HTTP-сервер для разработки и тестирования — без фреймворков, одной командой:

```text
jwebserver -p 8080 -d ./public
```

Сервер раздаёт статические файлы из каталога `./public` на порту 8080. Не предназначен для продакшена.

### JConsole и VisualVM

Графические инструменты мониторинга JVM:

```text
jconsole         # JMX-мониторинг: память, потоки, классы, MBeans
jvisualvm        # профилировщик: CPU, память, дампы потоков (с Java 8; Java 9+ — отдельная установка)
```

`jconsole` входит в JDK. Позволяет подключаться к локальным и удалённым JVM-процессам для наблюдения в реальном времени.

Типовой поток диагностики зависания: `jps` → `jstack` (найти блокировку, см. [[14. Многопоточность и конкурентность#Deadlock, Livelock, Starvation|deadlock]]) → `jmap -heap` (проверить память).

Для профилирования производительности — `jfr start`/`jfr summary`/`jfr view` (Flight Recorder: события GC, аллокаций, методов, см. [[15. JVM, память и профессиональная разработка#JIT-компиляция|JIT]]).

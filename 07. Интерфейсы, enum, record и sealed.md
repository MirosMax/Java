## Интерфейсы

Интерфейс — контракт, описывающий поведение. С Java 8 может содержать реализации по умолчанию; с Java 9 — приватные методы.

### Объявление и `implements`

```java
interface Drawable {
    void draw();              // абстрактный метод
}

class Circle implements Drawable {
    public void draw() { System.out.println("Рисуем круг"); }
}
```

Метод интерфейса по умолчанию `public abstract`. Реализация обязана дать `public` (нельзя сузить видимость).

### Реализация методов

Класс, реализующий интерфейс, обязан реализовать все его абстрактные методы (иначе должен быть абстрактным).

### Ссылки интерфейсного типа

Переменную можно объявить типом интерфейса:

```java
Drawable d = new Circle();
d.draw();
```

Это основа полиморфизма и слабой связанности (см. [[15. JVM, память и профессиональная разработка#Базовые принципы дизайна|принципы дизайна]]).

## Множественная реализация интерфейсов

В отличие от классов, интерфейсов класс реализует сколько угодно:

```java
interface Readable { void read(); }
interface Writable { void write(); }

class File implements Readable, Writable {
    public void read() { }
    public void write() { }
}
```

Это компенсирует запрет множественного наследования классов (см. [[06. Наследование и полиморфизм#Многоуровневое наследование|наследование]]).

## Поля интерфейсов

Поля интерфейса неявно `public static final` — это константы:

```java
interface Constants {
    int MAX_SIZE = 100;   // public static final int MAX_SIZE = 100;
}
```

## Default methods

Методы с реализацией по умолчанию — добавлены в Java 8, чтобы расширять интерфейсы без поломки реализующих классов:

```java
interface Greeter {
    String name();
    default String greet() { return "Привет, " + name(); }
}

class User implements Greeter {
    public String name() { return "Аня"; }
    // greet() унаследован
}

new User().greet();   // "Привет, Аня"
```

## Static methods в интерфейсах

Статические методы в интерфейсах — утилиты, вызываются через имя интерфейса:

```java
interface MathOps {
    static int square(int x) { return x * x; }
}

int s = MathOps.square(5);   // 25
```

## Private methods в интерфейсах

С Java 9 приватные методы скрывают общий код между default/static методами:

```java
interface Validator {
    default boolean check(String s) { return valid(s); }
    static boolean checkStatic(String s) { return valid(s); }

    private static boolean valid(String s) { return s != null && !s.isBlank(); }
}
```

## Конфликты default methods

При реализации двух интерфейсов с одинаковым default-методом — обязаны переопределить:

```java
interface A { default void hello() { System.out.println("A"); } }
interface B { default void hello() { System.out.println("B"); } }

class C implements A, B {
    public void hello() {
        A.super.hello();   // явный выбор реализации
    }
}
```

Правило приоритета: метод класса (включая унаследованный от суперкласса) побеждает default-метод интерфейса; суперкласс важнее интерфейса.

## Интерфейс против абстрактного класса

| Критерий | Интерфейс | Абстрактный класс |
| --- | --- | --- |
| Наследование | несколько интерфейсов | один суперкласс |
| Поля | только `public static final` | любые поля |
| Конструкторы | нет | есть |
| Состояние | не хранит | может хранить |
| Методы | abstract / default / static / private | любые |
| Назначение | контракт поведения (can-do) | общая база иерархии (is-a) |

```java
// интерфейс — что объект умеет
interface Flyable { void fly(); }

// абстрактный класс — чем объект является
abstract class Bird {
    abstract void sing();
}
```

Выбор: для описания возможностей — интерфейс; для общей реализации и состояния — абстрактный класс.

## Вложенные интерфейсы

Интерфейс может быть объявлен внутри класса или другого интерфейса:

```java
class Outer {
    interface Callback {
        void onDone();
    }
}

class Impl implements Outer.Callback {
    public void onDone() { }
}
```

## Enum

`enum` — тип с фиксированным набором констант.

### Объявление и константы

```java
enum Day {
    MONDAY, TUESDAY, WEDNESDAY, THURSDAY, FRIDAY, SATURDAY, SUNDAY
}
```

Каждая константа — экземпляр enum, неявно `static final`.

### Поля, методы, конструкторы

Enum — полноценный класс: может иметь поля, методы и конструкторы:

```java
enum Planet {
    MERCURY(3.3e23), EARTH(5.97e24), JUPITER(1.9e27);

    private final double mass;

    Planet(double mass) { this.mass = mass; }   // конструктор приватный
    double mass() { return mass; }
}
```

Конструктор enum всегда `private` — константы создаются только внутри enum.

### `values`, `valueOf`, `ordinal`

```java
Day[] all = Day.values();       // все константы
Day d = Day.valueOf("MONDAY");  // по имени
int idx = Day.FRIDAY.ordinal(); // 4 — позиция в объявлении
```

`valueOf` с неверным именем бросает `IllegalArgumentException`. `ordinal` использовать не рекомендуется — зависит от порядка объявления.

### Enum в `switch`

Enum хорошо сочетается со `switch` (см. [[02. Операторы и управление потоком#switch|switch]]):

```java
String label = switch (day) {
    case SATURDAY, SUNDAY -> "Выходной";
    default -> "Рабочий день";
};
```

## Record

С Java 16 `record` — компактное объявление неизменяемого класса-носителя данных.

### Назначение и компоненты

Автоматически создаёт конструктор, `accessor`-методы, `equals`, `hashCode`, `toString`:

```java
record Point(int x, int y) { }

Point p = new Point(3, 4);
p.x()    // 3 — accessor
p.toString()   // "Point[x=3, y=4]"
```

Все поля `final`, класс `final` — record неизменяем (см. [[05. Классы и объекты#Неизменяемые объекты|неизменяемость]]).

### Автоматические методы

- `equals`/`hashCode` — по всем компонентам.
- `toString` — читаемое представление.
- Accessor `name()` без префикса `get`.

### Канонический и компактный конструктор

Компактный конструктор — тело без параметров, для валидации:

```java
record Person(String name, int age) {
    public Person {                    // компактный конструктор
        if (age < 0) throw new IllegalArgumentException("age < 0");
    }
}
```

### Дополнительные методы

Можно добавлять методы и статические фабрики:

```java
record Point(int x, int y) {
    static Point origin() { return new Point(0, 0); }
    double distance() { return Math.sqrt(x * x + y * y); }
}
```

### Ограничения наследования

Record не может наследовать классы и не может быть суперклассом (неявно `final`). Реализовывать интерфейсы — может.

## Sealed classes

С Java 17 — ограничение иерархии: известный заранее набор наследников.

### `sealed`, `non-sealed`, `final`

```java
sealed interface Shape permits Circle, Square, Triangle { }

final class Circle implements Shape { }
non-sealed class Square implements Shape { }
final class Triangle implements Shape { }
```

- `final` — наследник без потомков.
- `non-sealed` — наследник открыт для дальнейшего наследования.
- Все разрешённые наследники обязаны быть в том же модуле/пакете.

### `permits`

Перечисляет разрешённые подтипы. Если подтипы объявлены в том же файле, `permits` можно опускать.

### Sealed interfaces

Интерфейсы тоже могут быть `sealed` — известен закрытый набор реализаций. Удобно вместе со `switch` и pattern matching (см. [[02. Операторы и управление потоком#Pattern matching в switch|pattern matching в switch]]):

```java
sealed interface Shape permits Circle, Square { }

double area(Shape s) {
    return switch (s) {
        case Circle c -> Math.PI * c.r() * c.r();
        case Square sq -> sq.side() * sq.side();
    };
}
```

Исчерпывающий `switch` по sealed-иерархии не требует `default`.

Энциклопедический справочник по языку Java для разработчика с базовыми знаниями программирования. Ориентир — **Java 21 (LTS)**.

## Как устроена заметка

- Ручное оглавление из вики-ссылок `[[#Заголовок|Заголовок]]`.
- Заголовки без номеров, глубина до 3–4 уровней.
- Короткие примеры кода (5–15 строк), таблицы сравнений, диаграммы Mermaid.
- Перекрёстные вики-ссылки между заметками.

## Порядок работы

1. Структура утверждена (см. `План.md` и `AGENTS.md`).
2. Заметки генерируются **по одной** в нумерационном порядке.
3. После каждой заметки — коммит (пушит пользователь).
4. Глоссарий `0. Термины и определения.md` дополняется по мере появления новых терминов.

## Покрытие

База построена по «Java. Полное руководство» (12-е изд.): покрыты часть I (язык), часть II (ядро библиотеки — строки, `java.lang`, коллекции, I/O, NIO, сеть, утилиты, regex, дата/время, конкурентность) и приложения (Javadoc, JShell). 

Исключены из базы: AWT/Swing/изображения (десктопный GUI — лишь краткий обзор в `15`), сервлеты (Jakarta EE), JavaBeans, RMI.

### Логика каждого исключения
Все они сводятся к **цели базы** (справочник по современному серверному/консольному Java для практикующего разработчика) и **актуальности на 2026 год**.

#### 1. AWT / Swing / изображения (гл. 25–28, 32–34)

**Что это**: десктопные GUI-фреймворки — окна, кнопки, меню, рисование, обработка событий мыши/клавиатуры, загрузка изображений.

**Почему исключены:**
- **Другая парадигма разработки.** Это отдельная область (клиентский десктоп), не связанная с синтаксисом языка. Наш справочник — про язык и стандартную библиотеку для **бэкенда/консоли**, где GUI не используется вообще.
- **Технология на спадке.** AWT — ровесник Java 1.0, Swing — 1998 год. Новые десктоп-приложения на Java пишут на **JavaFX** (который в книге даже не разобран детально). Включать устаревающие AWT/Swing в энциклопедию «современной Java 21» значило бы раздувать её устаревшим материалом — против нашего принципа из AGENTS.md.
- **Объём.** Только GUI в книге — ~10 глав (25–28, 32–34): события, AWT, элементы управления, изображения, Swing. Это треть книги про то, что современному серверному разработчику почти не нужно.
- **Что оставлено**: краткий обзор в `15` — ровно чтобы читатель **знал о существовании** (увидит в легаси-коде, поймёт `JButton`, `SwingUtilities.invokeLater`, модель событий) без погружения в детали.

#### 2. Сервлеты (гл. 36)

**Что это**: Java-компоненты для обработки HTTP-запросов на веб-сервере (Tomcat), пакет `jakarta.servlet`.

**Почему исключены:**
- **Это не Java-язык, а отдельная платформа** — Jakarta EE (бывшая Java EE). Сервлет — технология веб-приложений, со своим жизненным циклом, контейнером и зависимостями (`jakarta.servlet-api`). Ядро языка (что мы покрываем) от этого не зависит.
- **Современная практика идёт мимо «сырых» сервлетов.** В 2026 веб-разработка на Java — это Spring Boot, Quarkus, Micronaut, которые используют сервлеты под капотом, но разработчик почти никогда не пишет `HttpServlet` руками.
- **Правильное место** — отдельная база знаний по веб-разработке/Spring, а не справочник по языку. Включив сервлеты, мы открыли бы дверь в бесконечную смежную область (Spring, ORM, REST, безопасность), которая не входит в задачу.

#### 3. JavaBeans (гл. 35)

**Что это**: архитектурная спецификация компонентов-бинов: свойства (`getX`/`setX`), события, постоянство; инструменты визуального конструирования (Introspector, PropertyDescriptor).

**Почему исключены:**
- **Практически мёртвая технология.** Спецификация JavaBeans создавалась под визуальные GUI-среды (перетаскивание компонентов) конца 90-х. В современной разработке она не применяется как таковая.
- **Термин «bean» живёт, но в другом смысле** — в Spring/Java EE под «бином» понимают обычный управляемый объект, и это не имеет отношения к JavaBeans-спецификации. То есть знание гл. 35 не даёт ничего для современного кода, а создаёт путаницу терминов.
- **Паттерн `getX`/`setX`** уже покрыт в нашем `05` (геттеры/сеттеры) — практическая суть сохранилась без устаревшей обвязки.

#### 4. RMI (гл. 31, раздел)

**Что это**: Java Remote Method Invocation — вызов методов удалённых Java-объектов по сети.

**Почему исключены:**
- **Устарел и вытеснен.** RMI (Java 1.1) десятилетия как заменён распределёнными подходами: REST/HTTP, gRPC, message brokers (Kafka, RabbitMQ), Java RMI почти не используется в новых системах.
- **Связан с устаревшей Java-сериализацией** (которую мы уже помечаем в `12` как небезопасную и не рекомендуемую). Продвигать RMI значило бы тянуть за собой нерекомендуемую сериализацию.
- Упоминание одной строкой в `15` достаточно — чтобы читатель понял, встретив в легаси.

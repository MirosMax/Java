## Зачем нужны generics

Обобщения (Java 5) дают типобезопасность: компилятор проверяет типы на этапе компиляции, исключая ошибки приведения.

```java
// до generics — риск ClassCastException
List list = new ArrayList();
list.add("строка");
String s = (String) list.get(0);

// с generics — проверка на этапе компиляции
List<String> list = new ArrayList<>();
list.add("строка");
String s = list.get(0);   // приведение не нужно
```

Параметр типа указывается в угловых скобках `<...>`.

## Обобщённые классы

```java
class Box<T> {
    private T value;
    public void set(T value) { this.value = value; }
    public T get() { return value; }
}

Box<String> box = new Box<>();
box.set("hello");
String v = box.get();
```

Можно несколько параметров:

```java
class Pair<K, V> {
    private final K key;
    private final V value;
    Pair(K key, V value) { this.key = key; this.value = value; }
    K key() { return key; }
    V value() { return value; }
}
```

### Generic-конструкторы

Конструктор тоже может иметь собственный параметр типа:

```java
class Wrapper {
    <T> Wrapper(T value) { System.out.println("Обёрнут: " + value); }
}

new Wrapper("строка");   // тип T выведен как String
```

### Diamond-оператор и выведение типа

С Java 7 `<>` — пустой diamond, тип выводится из контекста. С Java 9 diamond работает и с анонимными классами:

```java
List<String> list = new ArrayList<>();     // тип из левой части
var map = new HashMap<String, List<Integer>>();   // с var (см. [[01. Основы языка Java#Выведение типа через var|var]])

Comparator<String> cmp = new Comparator<>() {     // Java 9: diamond + анонимный класс
    public int compare(String a, String b) { return a.compareTo(b); }
};
```

## Обобщённые интерфейсы

```java
interface Repository<T> {
    T findById(long id);
    void save(T entity);
}

class UserRepository implements Repository<User> {
    public User findById(long id) { ... }
    public void save(User u) { ... }
}
```

## Обобщённые методы

Параметр типа объявляется **перед** возвращаемым типом:

```java
static <T> T first(List<T> list) {
    return list.get(0);
}

String s = first(List.of("a", "b"));
```

Выведение типа аргумента происходит из контекста вызова; при необходимости тип задаётся явно:

```java
String t = Generics.<String>first(List.of("a"));   // явное указание T
```

Generic-методы не обязаны принадлежать generic-классу — это статические утилиты (см. `Collections` в [[10. Коллекции и структуры данных#Класс Collections|коллекциях]]).

## Ограниченные параметры типов

Ограничение верхней границей — параметр обязан быть подтипом заданного типа:

```java
static <T extends Number> double sum(List<T> list) {
    double s = 0;
    for (T x : list) s += x.doubleValue();
    return s;
}

sum(List.of(1, 2, 3));          // ок
// sum(List.of("a"));           // ошибка: String не Number
```

Множественные границы через `&` — первая должна быть классом (или `Object`), остальные — интерфейсы:

```java
<T extends Comparable<T> & Serializable>
// <T extends SomeClass & InterfaceA & InterfaceB>  — класс только первый
```

Ограничение накладывает на параметр типа и верхнюю границу при стирании: `<T extends Number>` стирается до `Number` (см. [[#Type erasure|type erasure]]).

## Wildcards

Wildcard `?` — неизвестный тип. Используется в сигнатурах для гибкости.

### `? extends T` (Producer)

Принимает `T` и его подтипы. Из такой коллекции **можно читать** элементы как `T`, но нельзя добавлять (`add` запрещён).

```java
void printNumbers(List<? extends Number> list) {
    for (Number n : list) System.out.println(n);   // чтение ок
    // list.add(1);  // ошибка
}

printNumbers(List.of(1, 2, 3));        // List<Integer>
printNumbers(List.of(1.5, 2.5));       // List<Double>
```

### `? super T` (Consumer)

Принимает `T` и его супертипы. В такую коллекцию **можно добавлять** `T`, но читать можно только как `Object`.

```java
void addAll(List<? super Integer> dest, List<Integer> src) {
    dest.addAll(src);   // добавление ок
}

List<Number> numbers = new ArrayList<>();
addAll(numbers, List.of(1, 2));
```

### Неограниченный `?`

Принимает любые типы; читать можно только `Object`:

```java
void printAll(List<?> list) {
    for (Object o : list) System.out.println(o);
}
```

## PECS

Мнемоника «Producer Extends, Consumer Super»:

- **Producer Extends**: коллекция, из которой читаем (производит значения), — `? extends T`.
- **Consumer Super**: коллекция, в которую пишем (потребляет значения), — `? super T`.

```java
static <T> void copy(List<? extends T> src, List<? super T> dst) {
    for (T item : src) dst.add(item);   // extends — читаем, super — пишем
}
```

Если коллекция и производит, и потребляет — обычный тип без wildcard.

## Ограничения generics

### Нельзя создать `new T()`

Из-за стирания типов (см. [[#Type erasure|type erasure]]) невозможно инстанцировать параметр типа:

```java
static <T> T create() {
    // return new T();  // ошибка
    return null;
}
```

### Generic-массивы

Создание массива параметризованного типа напрямую запрещено:

```java
// new List<String>[10];  // ошибка
List<String>[] arr = (List<String>[]) new List<?>[10];   // с предупреждением
```

### static и параметры типов

Статические члены не могут использовать параметр типа класса:

```java
class Box<T> {
    static T shared;   // ошибка: static не может ссылаться на параметр типа
}
```

### Примитивы и generics

Параметром типа может быть только ссылочный тип. Примитивы упаковываются (см. [[13. Дата, время, числа и полезные API#Autoboxing и unboxing|autoboxing]]):

```java
List<Integer> list = new ArrayList<>();
list.add(42);   // автоупаковка int -> Integer
```

### Исключения и generics

- Нельзя `throw`/`catch` параметр типа: `catch (T e)` — ошибка, классы исключений не могут быть обобщёнными.
- `instanceof` с параметризованным типом невозможен — только с raw/`?`:

```java
// if (x instanceof List<String>)  // ошибка: непараметризуемый instanceof
if (x instanceof List<?> lst) { ... }   // ок: wildcard
```

### Generic-класс как аргумент исключения в `throws`

```java
static <T extends Exception> void rethrow(Exception e) throws T {
    throw (T) e;   // unchecked приведение — «обход» checked-проверки
}
```

Это трюк для проброса checked исключения через generic-метод; использовать осознанно.

## Raw types

Raw type — использование обобщённого класса без параметра типа. Даёт предупреждение и теряет безопасность:

```java
List raw = new ArrayList();          // raw type, предупреждение
List<String> typed = new ArrayList<>();

raw.add(123);                        // ок для raw
// typed.add(123);                   // ошибка компиляции
```

Смешивание raw и параметризованных ссылок на один объект опасно — ошибка всплывёт в неожиданном месте:

```java
List<String> typed = new ArrayList<>();
List raw = typed;            // расширение до raw
raw.add(123);                // компилируется!
String s = typed.get(0);     // ClassCastException в рантайме
```

Использовать raw types не стоит (см. [[#Зачем нужны generics|зачем нужны generics]]). Исключение — совместимость с легаси-кодом до Java 5 и некоторые reflection-операции.

## Type erasure

Параметры типов существуют только на этапе компиляции. Во время выполнения они **стираются** до границы (или `Object`):

```java
// исходный код
List<String> a = new ArrayList<>();
List<Integer> b = new ArrayList<>();

// после стирания оба — List
```

Это делает generics совместимыми с кодом до Java 5, но у них нет информации о типе во время выполнения.

## Bridge methods

Компилятор генерирует мостовые методы для сохранения полиморфизма при переопределении с generics:

```java
class Node implements Comparable<Node> {
    public int compareTo(Node o) { ... }
}

// компилятор добавляет неявный bridge-метод:
public int compareTo(Object o) { return compareTo((Node) o); }
```

Bridge-методы нужны для корректной работы виртуальной машины после стирания.

## Generics и наследование

`List<String>` **не** является подтипом `List<Object>` — обобщённые типы инвариантны (см. [[#Ковариантность, контравариантность и инвариантность|инвариантность]]):

```java
List<String> strings = new ArrayList<>();
// List<Object> objs = strings;   // ошибка
```

Но класс может наследовать обобщённый с конкретным типом:

```java
class StringList extends ArrayList<String> { }
```

## Ковариантность, контравариантность и инвариантность

| Отношение | Свойство | Пример |
| --- | --- | --- |
| Ковариантность | подтип сохраняется | массивы: `String[]` — подтип `Object[]` |
| Инвариантность | подтип не сохраняется | `List<String>` не подтип `List<Object>` |
| Контравариантность | подтип инвертируется | `List<? super String>` принимает `List<Object>` |

Массивы ковариантны, но это источник `ArrayStoreException`:

```java
Object[] arr = new String[3];
arr[0] = 42;   // ArrayStoreException (проверка на этапе выполнения)
```

Generics инвариантны — проверка на этапе компиляции. Гибкость достигается wildcards `extends`/`super` (см. [[#PECS|PECS]]):

```java
// ковариантность через wildcard: можно читать
List<? extends Number> nums = new ArrayList<Integer>();

// контравариантность через wildcard: можно писать
List<? super Integer> dest = new ArrayList<Number>();

// обычный тип — инвариантен: только точное соответствие
List<Integer> exact = new ArrayList<Integer>();
```

### Правило подстановки

Подстановка типа допустима, если подтип не нарушает безопасность чтения/записи:
- **чтение** безопасно, когда тип «не шире» заявленного — `? extends`.
- **запись** безопасна, когда тип «не уже» заявленного — `? super`.

Это и есть суть PECS (см. [[#PECS|PECS]]): extends — для чтения (producer), super — для записи (consumer).

## Type tokens (гетерогенные контейнеры)

Из-за стирания типов (см. [[#Type erasure|type erasure]]) параметризованный тип в рантайме неизвестен. Приём — передавать `Class<T>` (type token) и приводить с проверкой:

```java
class Container {
    private final Map<Class<?>, Object> store = new HashMap<>();

    <T> void put(Class<T> type, T value) {
        store.put(type, type.cast(value));   // type.cast — безопасное приведение
    }

    <T> T get(Class<T> type) {
        return type.cast(store.get(type));
    }
}

Container c = new Container();
c.put(String.class, "значение");
String s = c.get(String.class);   // ок
```

`Class.cast` — типизированное приведение, избавляет от raw-каста (см. [[15. JVM, память и профессиональная разработка#Reflection|reflection]]).

## Reifiable и non-reifiable типы

**Reifiable** — типы, информация о которых полностью доступна во время выполнения. К ним относятся: примитивы, raw-типы, `List<?>`, `List<? extends Object>`, массивы.

**Non-reifiable** — типы, которые из-за стирания (см. [[#Type erasure|type erasure]]) теряют часть информации: `List<String>`, `List<List<Integer>>`.

```java
// reifiable
List<?> wild = new ArrayList<String>();  // OK
if (wild instanceof List<?>) { }        // OK — wildcard reifiable

// non-reifiable — нельзя использовать с instanceof
// if (wild instanceof List<String>) { }  // ОШИБКА: не reifiable
```

Следствия:
- `instanceof` с конкретным параметром типа запрещён — только с wildcard'ом
- Массивы non-reifiable типов запрещены: `new List<String>[10]` — ошибка
- Varargs с non-reifiable типами дают предупреждение (`@SafeVarargs` для подавления)

## Wildcard capture

Компилятор может вывести конкретный тип для wildcard'а при вызове generic-метода:

```java
void swap(List<?> list, int i, int j) {
    // list.set(i, list.get(j));  // ОШИБКА: ? может не совпадать
    swapHelper(list, i, j);        // helper с capture
}

// хелпер с захватом wildcard'а
private static <T> void swapHelper(List<T> list, int i, int j) {
    T tmp = list.get(i);
    list.set(i, list.get(j));
    list.set(j, tmp);
}
```

Wildcard capture позволяет писать методы с `List<?>`, которые безопасно модифицируют коллекцию. Компилятор «захватывает» неизвестный тип как `T` в методе-хелпере.

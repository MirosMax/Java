## Обзор пакетов

Расширенные утилиты конкурентности (`java.util.concurrent` и подпакеты) дополняют базовые средства (см. [[14. Многопоточность и конкурентность|многопоточность]]):

| Пакет | Назначение |
| --- | --- |
| `java.util.concurrent` | синхронизаторы, executor'ы, коллекции, `TimeUnit` |
| `java.util.concurrent.atomic` | атомарные классы, `LongAdder` (см. [[14. Многопоточность и конкурентность#Atomic classes|atomic]]) |
| `java.util.concurrent.locks` | явные блокировки, `Condition` (см. [[14. Многопоточность и конкурентность#Locks|locks]]) |

## Синхронизаторы

Высокоуровневые механизмы координации потоков — «готовые сценарии» вместо ручного `wait`/`notify` (см. [[14. Многопоточность и конкурентность#Мониторы|мониторы]]).

### `Semaphore`

Ограничение числа потоков, одновременно входящих в секцию:

```java
Semaphore permits = new Semaphore(3);   // максимум 3 потока

permits.acquire();      // ждать разрешение (блокирует)
try {
    // критическая секция — не более 3 потоков
} finally {
    permits.release();  // вернуть разрешение
}

boolean got = permits.tryAcquire(2, TimeUnit.SECONDS);   // с таймаутом
```

Варианты и справедливость:

```java
new Semaphore(3, true);     // честный режим — FIFO-очередь ожидающих
semaphore.acquireUninterruptibly();   // игнорировать прерывание
semaphore.availablePermits();         // свободные разрешения
semaphore.drainPermits();             // забрать все оставшиеся
```

Типовое применение: ограничение пула соединений, rate-limiting (лимит одновременных запросов).

### `CountDownLatch`

Ожидание, пока счётчик не станет нулём (одноразовый):

```java
CountDownLatch start = new CountDownLatch(1);   // «стартовый пистолет»

// потоки-участники ждут
start.await();
// ...

// главный поток даёт старт
start.countDown();
```

Применение: одновременный старт N потоков, ожидание завершения N задач.

```java
boolean finished = start.await(5, TimeUnit.SECONDS);   // ожидание с таймаутом
long remaining = start.getCount();                     // оставшийся счётчик
```

**Одноразовость**: после обнуления счётчика `CountDownLatch` не переиспользуется — для повторного барьера нужен `CyclicBarrier`.

### `CyclicBarrier`

Барьер, через который потоки проходят **вместе**, когда соберутся все (многоразовый):

```java
CyclicBarrier barrier = new CyclicBarrier(3);   // ждём 3 потока

// каждый поток
barrier.await();    // блокируется, пока все 3 не вызовут await
// дальше все продолжают одновременно
```

Барьерное действие — выполняется, когда барьер собран (до освобождения потоков):

```java
CyclicBarrier barrier = new CyclicBarrier(3, () -> {
    System.out.println("Все собрались, старт!");   // один раз за проход
});
```

Отличие от `CountDownLatch`: барьер переиспользуем (цикличен), `await` возвращает после сбора всех.

### `Exchanger`

Обмен данными между двумя потоками:

```java
Exchanger<String> exchanger = new Exchanger<>();

// поток A
String received = exchanger.exchange("от A");
// поток B
String got = exchanger.exchange("от B");
```

Каждый `exchange` блокируется, пока второй поток не вызовет свой.

### `Phaser`

Гибкая многофазная координация (продвинутый `CyclicBarrier`):

```java
Phaser phaser = new Phaser(1);   // регистрация текущего потока

phaser.register();               // добавить участника
phaser.arriveAndAwaitAdvance();  // прибыть и ждать фазу
phaser.arriveAndDeregister();    // прибыть и выйти из фазы
phaser.advance();                // число завершённых фаз
```

Отличия от `CyclicBarrier`:

- **Число участников динамическое** — `register()`/`arriveAndDeregister()` меняют его на лету.
- Несколько **фаз**: поток может участвовать в первой фазе и выйти перед второй.
- `getPhase()` — номер текущей фазы; `onAdvance(phase, parties)` — действие при завершении фазы (переопределяется в подклассе).

```java
class WorkerPhaser extends Phaser {
    protected boolean onAdvance(int phase, int parties) {
        System.out.println("Фаза " + phase + " завершена");
        return parties == 0;   // true — завершить phaser
    }
}
```

Применение: многошаговый параллельный конвейер, где участники меняются между шагами.

## TimeUnit

Перечисление единиц времени (`NANOSECONDS`, `MICROSECONDS`, `MILLISECONDS`, `SECONDS`, `MINUTES`, `HOURS`, `DAYS`):

```java
Thread.sleep(TimeUnit.SECONDS.toMillis(2));   // 2000 мс

long nanos = TimeUnit.MINUTES.toNanos(5);     // 5 мин в наносекундах

// таймауты у executor'ов и блокировок
pool.awaitTermination(10, TimeUnit.SECONDS);
lock.tryLock(1, TimeUnit.MINUTES);
```

Конвертация и удобные методы:

```java
TimeUnit.SECONDS.convert(90, TimeUnit.MINUTES);   // 5400
TimeUnit.HOURS.convert(5400, TimeUnit.SECONDS);   // 1

TimeUnit.SECONDS.sleep(2);            // Thread.sleep без try/catch-шума
TimeUnit.MILLISECONDS.timedJoin(thread, 500);     // join с таймаутом
TimeUnit.SECONDS.timedWait(obj, 2);   // wait с таймаутом
```

## Дополнительные конкурентные коллекции

Помимо базовых (см. [[14. Многопоточность и конкурентность#Concurrent collections|concurrent collections]]):

### `SynchronousQueue`

Очередь без буфера: каждая `put` блокируется до парной `take` — «прямая передача»:

```java
SynchronousQueue<String> q = new SynchronousQueue<>();
q.put("задача");        // блокирует, пока другой поток не вызовет take()
String item = q.take();
```

### `LinkedTransferQueue`

Очередь с поддержкой «передачи» напрямую (если есть ожидающий потребитель) и буферизации:

```java
LinkedTransferQueue<String> q = new LinkedTransferQueue<>();
q.transfer("важно");    // передать напрямую, если кто-то ждёт
q.offer("обычное");     // иначе в буфер
```

### `DelayQueue`

Очередь, из которой элемент доступен после заданной задержки:

```java
class Task implements Delayed {
    public long getDelay(TimeUnit unit) { ... }
    public int compareTo(Delayed o) { ... }
}

DelayQueue<Task> q = new DelayQueue<>();
q.put(new Task(...));
Task ready = q.take();   // вернётся только после истечения задержки
```

### `ConcurrentSkipListSet`

Потокобезопасный отсортированный набор (аналог `TreeSet` для многопоточности, см. [[10. Коллекции и структуры данных#Set|Set]]):

```java
ConcurrentSkipListSet<Integer> set = new ConcurrentSkipListSet<>();
set.add(3); set.add(1);
set.first();   // 1
```

## `StampedLock`

Продвинутая блокировка (Java 8) с оптимистичным чтением — быстрее `ReadWriteLock` при частом чтении (см. [[14. Многопоточность и конкурентность#ReadWriteLock|ReadWriteLock]]):

```java
StampedLock lock = new StampedLock();

long stamp = lock.writeLock();       // эксклюзивная запись
try { ... } finally { lock.unlockWrite(stamp); }

// оптимистичное чтение: без блокировки, с проверкой валидности
long optimistic = lock.tryOptimisticRead();
int v = read();
if (!lock.validate(optimistic)) {    // состояние изменилось
    long readStamp = lock.readLock();   // классическое чтение
    try { v = read(); } finally { lock.unlockRead(readStamp); }
}
```

Подходит для высококонкурентного чтения с редкими записями (например, снапшоты конфигурации).

## Fork/Join Framework

Фреймворк для параллельных вычислений «разделяй и властвуй» (Java 7). Использует work-stealing: потоки воруют задачи из чужих очередей, загрузка ядер сбалансирована.

### `ForkJoinPool` и `RecursiveTask`

```java
class SumTask extends RecursiveTask<Long> {
    private final long[] arr;
    private final int from, to;
    private static final int THRESHOLD = 10_000;

    SumTask(long[] arr, int from, int to) { ... }

    @Override
    protected Long compute() {
        if (to - from <= THRESHOLD) {          // базовый случай: прямой подсчёт
            long sum = 0;
            for (int i = from; i < to; i++) sum += arr[i];
            return sum;
        }
        int mid = (from + to) / 2;             // разделение
        SumTask left = new SumTask(arr, from, mid);
        SumTask right = new SumTask(arr, mid, to);
        left.fork();                           // запустить левую часть в пуле
        return right.compute() + left.join();  // досчитать правую и ждать левую
    }
}

long[] data = ...;
long sum = new ForkJoinPool().invoke(new SumTask(data, 0, data.length));
```

### `ForkJoinPool.commonPool`

Общий пул (по числу ядер) — то, что используют parallel streams (см. [[11. Лямбда-выражения и Stream API#Parallel streams|parallel streams]]); отдельный пул создают для изоляции или настройки параллелизма:

```java
ForkJoinPool pool = new ForkJoinPool(4);          // 4 потока
long sum = pool.invoke(new SumTask(data, 0, data.length));

ForkJoinPool common = ForkJoinPool.commonPool();
common.getParallelism();                          // число потоков
```

### `RecursiveAction`

Вариант без результата (void-задача):

```java
class FillAction extends RecursiveAction {
    private final int[] arr;
    private final int from, to;
    private static final int THRESHOLD = 1000;

    FillAction(int[] arr, int from, int to) { ... }

    @Override
    protected void compute() {
        if (to - from <= THRESHOLD) {
            for (int i = from; i < to; i++) arr[i] = 1;
            return;
        }
        int mid = (from + to) / 2;
        invokeAll(new FillAction(arr, from, mid),   // запустить обе и дождаться
                  new FillAction(arr, mid, to));
    }
}
```

`invokeAll(...)` принимает несколько задач сразу — удобнее пары `fork()`/`join()` для независимых веток.

### Принципы использования

- Размер подзадачи — в пределах «разумной» границы (`THRESHOLD`), иначе накладные расходы превышают выигрыш.
- `fork()` асинхронно ставит задачу; `join()` ждёт результат.
- `invoke`/`invokeAll` — удобные точки входа.
- Отмена: `task.cancel(true)`; состояние — `isDone()`/`isCancelled()`/`isCompletedNormally()`.

```java
SumTask task = new SumTask(data, 0, data.length);
pool.execute(task);            // асинхронный запуск
long result = task.join();     // дождаться результата

task.cancel(true);             // отмена (прервать)
task.isCancelled();
task.isCompletedAbnormally();  // завершилась ошибкой/отменой
task.getException();           // причина исключения (ForkJoinTask)
```

Fork/Join лежит в основе parallel streams (см. [[11. Лямбда-выражения и Stream API#Parallel streams|parallel streams]]), но пригоден и для явных алгоритмов, не выражаемых стримами.

## LockSupport

Низкоуровневый механизм блокировки/пробуждения потоков (основа всех `Lock` и синхронизаторов):

```java
// приостановка потока
LockSupport.park();                // блокируется до unpark
LockSupport.parkNanos(1_000_000); // с таймаутом

// пробуждение
Thread t = Thread.currentThread();
LockSupport.unpark(t);             // разрешить выполнение
```

В отличие от `Object.wait()`/`notify()`:
- Не требует монитора (`synchronized`)
- `unpark` может быть вызван **до** `park` — поток не заблокируется (разрешение накапливается)
- Не бросает `InterruptedException` (проверять флаг прерывания)

## Flow API (Reactive Streams)

`java.util.concurrent.Flow` (Java 9+) — реализация Reactive Streams: асинхронная обработка потоков данных с backpressure (регулированием скорости):

```java
// простой подписчик
class MySubscriber implements Flow.Subscriber<Integer> {
    private Flow.Subscription sub;

    public void onSubscribe(Flow.Subscription sub) {
        this.sub = sub;
        sub.request(1);   // запросить первый элемент
    }
    public void onNext(Integer item) {
        System.out.println(item);
        sub.request(1);   // запросить следующий
    }
    public void onError(Throwable t) { }
    public void onComplete() { }
}

// SubmissionPublisher — простой издатель
try (var pub = new SubmissionPublisher<Integer>()) {
    pub.subscribe(new MySubscriber());
    pub.submit(1);
    pub.submit(2);
}
```

Компоненты Flow API:
- `Publisher` — поставщик данных
- `Subscriber` — потребитель
- `Subscription` — управление подпиской (request, cancel)
- `Processor` — и Publisher, и Subscriber (трансформация)

Используется в реактивных библиотеках (Project Reactor, RxJava) как низкоуровневая основа.

## Сравнение подходов

| Подход | Назначение | Когда |
| --- | --- | --- |
| `synchronized` / `Lock` | защита критической секции | изменение общего состояния |
| Atomic-классы | атомарные счётчики/флаги | одиночные операции |
| Синхронизаторы (`Semaphore`, `Latch`, `Barrier`) | координация потоков | сценарии «старт/барьер/лимит» |
| Executors + `Future` | пул задач с результатом | набор независимых задач |
| Fork/Join | «разделяй и властвуй» | рекурсивный параллелизм по данным |
| `CompletableFuture` | асинхронные цепочки | композиция асинхронных операций |
| Virtual threads | массовый блокирующий I/O | много лёгких задач (см. [[14. Многопоточность и конкурентность#Virtual threads|virtual threads]]) |

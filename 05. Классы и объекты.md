## Создание классов

Класс — шаблон объекта: описывает поля (состояние) и методы (поведение).

```java
class Point {
    int x;   // поле
    int y;

    double distanceToOrigin() {   // метод
        return Math.sqrt(x * x + y * y);
    }
}
```

### Поля и методы

Поля хранят состояние объекта; методы — операции над ним. Поля имеют значения по умолчанию (см. [[01. Основы языка Java#Значения по умолчанию|значения по умолчанию]]).

### Объекты и оператор `new`

Объект (экземпляр) создаётся оператором `new` — выделяется память в куче и вызывается конструктор.

```java
Point p = new Point();   // создание объекта
p.x = 3;
p.y = 4;
p.distanceToOrigin()     // 5.0
```

## Ссылки на объекты

Переменная ссылочного типа хранит адрес объекта, а не сам объект.

### `null`

Ссылка, не указывающая ни на какой объект. Обращение по `null` — `NullPointerException`.

```java
Point p = null;
// p.x = 1;  // NullPointerException
```

### Копирование ссылок

Присваивание копирует ссылку — объект общий:

```java
Point a = new Point();
Point b = a;      // a и b ссылаются на один объект
b.x = 10;
a.x              // 10
```

### Несколько ссылок на один объект

Много ссылок указывают на один объект; объект жив, пока есть хотя бы одна ссылка (см. [[15. JVM, память и профессиональная разработка#Garbage Collector|сборку мусора]]).

## Ключевое слово `this`

`this` — ссылка на текущий объект внутри методов и конструкторов.

### Обращение к полям

```java
class Point {
    int x;
    void setX(int x) {
        this.x = x;   // this.x — поле, x — параметр
    }
}
```

### Разрешение конфликтов имён

Когда параметр перекрывает поле, `this` различает их. Без конфликта `this` можно опускать.

### Возвращение `this`

Позволяет строить цепочки вызовов (fluent API):

```java
class Builder {
    private String name;
    Builder name(String n) { this.name = n; return this; }
}

var b = new Builder().name("Java");
```

### Вызов конструктора через `this()`

Передача работы другому конструктору того же класса:

```java
class Point {
    int x, y;
    Point(int x, int y) { this.x = x; this.y = y; }
    Point() { this(0, 0); }   // вызов конструктора с параметрами
}
```

`this(...)` должен быть первой инструкцией конструктора.

## Конструкторы

Специальный метод: имя совпадает с классом, нет возвращаемого типа. Вызывается при `new`.

### Конструктор без параметров

Если конструкторов нет, компилятор добавляет конструктор по умолчанию (без параметров, пустой).

```java
class Demo {
    Demo() { }   // явный пустой конструктор
}
```

### Конструкторы с параметрами

Инициализация состояния при создании:

```java
class Person {
    String name;
    Person(String name) { this.name = name; }
}
```

### Перегрузка

Конструкторы перегружаются как методы (см. [[04. Методы и параметры#Перегрузка методов|перегрузку]]):

```java
class Rect {
    int w, h;
    Rect(int w, int h) { this.w = w; this.h = h; }
    Rect(int side) { this(side, side); }   // квадрат
    Rect() { this(1, 1); }
}
```

### Цепочки конструкторов

Один конструктор вызывает другой через `this(...)` — избегает дублирования.

### Значения по умолчанию

Поля до присваивания в конструкторе имеют значения по умолчанию (числа — 0, ссылки — null).

### Копирующий конструктор

Копия состояния другого объекта — современная альтернатива `clone()`:

```java
class Point {
    private final int x, y;
    Point(int x, int y) { this.x = x; this.y = y; }
    Point(Point other) { this(other.x, other.y); }   // копия
}

Point a = new Point(3, 4);
Point b = new Point(a);   // независимый объект с тем же состоянием
```

### `private`-конструктор

Конструктор `private` запрещает создание экземпляров извне — используется в утилитных классах и синглтонах:

```java
class MathUtils {
    private MathUtils() { }   // нельзя new MathUtils()

    static int square(int x) { return x * x; }
}
```

```java
class Config {
    private static final Config INSTANCE = new Config();   // синглтон
    private Config() { }
    static Config get() { return INSTANCE; }
}
```

### Фабричные методы

Статические методы создания вместо прямых конструкторов — гибкость имени и логики (см. `valueOf`/`of` в [[13. Дата, время, числа и полезные API#Парсинг чисел|wrapper-классах]]):

```java
class Point {
    private Point(int x, int y) { ... }
    static Point origin() { return new Point(0, 0); }   // именованная фабрика
    static Point of(int x, int y) { return new Point(x, y); }
}

Point p = Point.origin();
```

### Конструкторы и наследование

Цепочка конструкторов через `super(...)` при наследовании — см. [[06. Наследование и полиморфизм#Цепочка конструкторов|цепочку конструкторов]].

## Инициализация объектов

### Инициализаторы полей

Поля можно инициализировать прямо в объявлении:

```java
class Account {
    double balance = 1000.0;   // значение по умолчанию для новых объектов
}
```

### Блоки инициализации

Блок `{ }` в классе выполняется при каждом создании объекта.

```java
class Demo {
    int x;
    { x = 10; }   // блок инициализации экземпляра
}
```

### Порядок выполнения

1. Поля и блоки инициализации — в порядке их появления в коде.
2. Затем тело конструктора.

```java
class Demo {
    int a = init("поле a");       // 1
    { init("блок"); }              // 2
    Demo() { init("конструктор"); } // 3
}
```

Статические поля и статические блоки инициализируются один раз при загрузке класса (см. [[#Ключевое слово static|static]]) — **до** любого создания объекта и в порядке появления:

```java
class Config {
    static String first = load("поле");    // 1
    static { load("стат. блок"); }          // 2
}
```

### Порядок при наследовании

При создании объекта подкласса инициализация идёт сверху вниз по цепочке наследования: сначала статические члены суперкласса, затем статические подкласса, затем поля/блоки суперкласса, его конструктор, и так далее вниз (см. [[06. Наследование и полиморфизм#Цепочка конструкторов|цепочку конструкторов]]).

## Управление доступом

Модификаторы доступа контролируют видимость членов класса.

| Модификатор | Класс | Пакет | Подкласс | Все |
| --- | --- | --- | --- | --- |
| `private` | да | нет | нет | нет |
| (package-private) | да | да | нет | нет |
| `protected` | да | да | да | нет |
| `public` | да | да | да | да |

### `private`

Доступен только внутри своего класса — основа инкапсуляции.

### package-private

Без модификатора. Доступен внутри того же пакета (см. [[15. JVM, память и профессиональная разработка#Пакеты|пакеты]]).

### `protected`

Доступен в пакете и в подклассах (включая другие пакеты).

### `public`

Доступен везде.

## Инкапсуляция

Скрытие состояния класса и контролируемый доступ к нему (см. [[0. Термины и определения#Объектно-ориентированное программирование|инкапсуляцию]]).

### Скрытие состояния

Поля делают `private` — прямой доступ снаружи невозможен.

### Getters и Setters

Контролируемые методы доступа:

```java
class BankAccount {
    private double balance;

    public double getBalance() { return balance; }

    public void deposit(double amount) {
        if (amount <= 0) throw new IllegalArgumentException("Сумма должна быть > 0");
        balance += amount;
    }
}
```

### Проверка входных данных

Сеттеры проверяют инварианты до изменения состояния.

### Неизменяемые объекты

Все поля `final`, нет сеттеров, нет мутирующих методов — объект нельзя изменить после создания. Такие объекты безопасно разделять между потоками. Готовые примеры — `record` (см. [[07. Интерфейсы, enum, record и sealed#Record|record]]) и классы `String`/`LocalDate`.

## Ключевое слово `static`

Статические члены принадлежат классу, а не экземпляру.

### Статические поля

Одна копия на класс, общая для всех объектов:

```java
class Counter {
    static int total = 0;
    Counter() { total++; }
}
```

### Статические методы

Вызываются через имя класса, работают только со статическими данными (см. [[04. Методы и параметры#Статические методы|статические методы]]).

```java
Math.max(1, 2)   // статический метод
```

### Статические блоки

Инициализация статических полей при загрузке класса:

```java
class Config {
    static final String VERSION;
    static {
        VERSION = loadVersion();
    }
}
```

### Общие данные класса

Статические поля — естественное место для общих счётчиков и конфигурации. Потокобезопасность при мутации — отдельная забота (см. [[14. Многопоточность и конкурентность#Race condition|race condition]]).

## Ключевое слово `final`

### Финальные переменные

Значение нельзя изменить после инициализации:

```java
final int MAX = 100;
// MAX = 200;  // ошибка
```

### Финальные поля

Должны быть инициализированы в объявлении или в конструкторе — один раз. **В каждом конструкторе** класса (иначе ошибка компиляции):

```java
class Point {
    final int x;               // обязана получить значение
    Point(int x) { this.x = x; }   // ок
    // Point() { }             // ошибка: x не инициализировано
}
```

Связано с неизменяемостью (см. [[#Неизменяемые объекты|неизменяемые объекты]]) и гарантией видимости после публикации (см. [[14. Многопоточность и конкурентность#Visibility и Java Memory Model|Java Memory Model]]).

### Финальные ссылки

Запрещает переприсваивание ссылки, но не меняет сам объект:

```java
final StringBuilder sb = new StringBuilder("a");
sb.append("b");   // ок — объект меняется
// sb = new StringBuilder(); // ошибка
```

### Константы и `static final`

Классическая константа — `static final` (примитив или неизменяемый объект):

```java
class MathConstants {
    static final double PI = 3.141592653589793;
}
```

Для перечислений констант лучше `enum` (см. [[07. Интерфейсы, enum, record и sealed#Enum|enum]]).

## Вложенные классы

Класс, объявленный внутри другого класса.

### Статические вложенные классы

Объявлены со `static`. Не связаны с экземпляром внешнего класса:

```java
class Outer {
    static class Nested {
        void hello() { System.out.println("nested"); }
    }
}

Outer.Nested n = new Outer.Nested();
```

### Внутренние классы

Без `static`. Экземпляр внутреннего класса привязан к экземпляру внешнего:

```java
class Outer {
    class Inner {
        void hello() { System.out.println("inner"); }
    }
}

Outer o = new Outer();
Outer.Inner i = o.new Inner();
```

### Локальные классы

Определяются внутри метода; видны только в нём:

```java
void process() {
    class Helper {
        int doubleIt(int x) { return x * 2; }
    }
    var h = new Helper();
    h.doubleIt(3);
}
```

Локальный класс может обращаться к `effectively final` переменным метода (см. [[11. Лямбда-выражения и Stream API#Захват переменных|effectively final]]).

### Анонимные классы

Класс без имени, создаётся на месте — обычно для разовой реализации интерфейса:

```java
Runnable r = new Runnable() {
    public void run() { System.out.println("run"); }
};
```

С Java 8 анонимные классы для функциональных интерфейсов вытеснены лямбдами (см. [[11. Лямбда-выражения и Stream API#Лямбда-выражения|лямбды]]).

## Паттерн Builder

Альтернатива конструкторам с множеством параметров — пошаговое построение объекта с именованными сеттерами:

```java
class Pizza {
    private final String dough;
    private final String sauce;
    private final boolean cheese;
    private final boolean pepperoni;

    private Pizza(Builder b) {
        this.dough = b.dough;
        this.sauce = b.sauce;
        this.cheese = b.cheese;
        this.pepperoni = b.pepperoni;
    }

    static class Builder {
        private String dough = "тонкое";
        private String sauce = "томатный";
        private boolean cheese = true;
        private boolean pepperoni = false;

        Builder dough(String d) { this.dough = d; return this; }
        Builder sauce(String s) { this.sauce = s; return this; }
        Builder cheese(boolean c) { this.cheese = c; return this; }
        Builder pepperoni(boolean p) { this.pepperoni = p; return this; }
        Pizza build() { return new Pizza(this); }
    }
}

Pizza pizza = new Pizza.Builder()
        .dough("толстое")
        .cheese(false)
        .build();
```

Когда использовать Builder: класс с 4+ параметрами (особенно одинакового типа), когда нужны значения по умолчанию.

## equals и hashCode

### Зачем переопределять

`Object.equals()` сравнивает ссылки — два разных объекта с одинаковым состоянием считаются неравными. Для сравнения по содержимому переопределяют `equals`:

```java
class Point {
    private final int x, y;

    @Override
    public boolean equals(Object o) {
        if (this == o) return true;                       // ссылочное равенство
        if (o == null || getClass() != o.getClass()) return false;
        Point p = (Point) o;
        return x == p.x && y == p.y;
    }

    @Override
    public int hashCode() {
        return Objects.hash(x, y);
    }
}
```

### Контракт equals

- **Рефлексивность**: `x.equals(x)` → true
- **Симметричность**: `x.equals(y)` ↔ `y.equals(x)`
- **Транзитивность**: `x.equals(y) && y.equals(z)` → `x.equals(z)`
- **Консистентность**: повторные вызовы дают тот же результат (если состояние не менялось)
- **null**: `x.equals(null)` → false

### Контракт hashCode

- Если `equals` возвращает true, `hashCode` **обязан** совпадать
- Если `hashCode` совпадает, `equals` **не обязан** быть true (коллизия)

### equals/hashCode и наследование

Подкласс с дополнительными полями ломает симметрию `equals`. Решение: композиция вместо наследования, или `record` (см. [[07. Интерфейсы, enum, record и sealed#Record|record]]).

### Автоматическая генерация

Современные инструменты генерируют `equals`/`hashCode`:
- IDE (IntelliJ, Eclipse) — через меню Generate
- Lombok — `@EqualsAndHashCode`
- Record — автоматически по всем компонентам

## Клонирование объектов

### `clone()` из `Object`

Устаревший механизм. Класс должен реализовать `Cloneable` (маркерный интерфейс) и переопределить `clone`:

```java
class Point implements Cloneable {
    private int x, y;

    @Override
    public Point clone() {
        try {
            return (Point) super.clone();   // поверхностное копирование
        } catch (CloneNotSupportedException e) {
            throw new AssertionError(e);    // не произойдёт, т.к. implements Cloneable
        }
    }
}
```

**Проблемы `clone()`**:
- `CloneNotSupportedException` — checked, неудобно
- Поверхностное копирование (shallow copy) — ссылочные поля общие
- Непрозрачный вызов `super.clone()` (через native-метод)

### Современные альтернативы

```java
// копирующий конструктор
public Point(Point other) {
    this.x = other.x;
    this.y = other.y;
}

// фабричный метод copy
public static Point copyOf(Point p) {
    return new Point(p.x, p.y);
}

// record — автоматически
record Point(int x, int y) { }
Point p2 = new Point(p.x(), p.y());
```

## Класс против record

| Характеристика | Класс | Record (Java 16+) |
| --- | --- | --- |
| Назначение | любая логика | носитель данных |
| Конструктор | можно любой | канонический (авто) |
| `equals`/`hashCode` | нужно писать | авто |
| `toString` | нужно писать | авто |
| Accessor'ы | `getX()` | `x()` |
| Изменяемость | можно mutable | неизменяем |
| Наследование | полное | `final` класс |

Record не заменяет классы — он заменяет **dto/pojo/data holder** (см. [[07. Интерфейсы, enum, record и sealed#Record|подробнее]]).

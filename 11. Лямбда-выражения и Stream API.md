## Лямбда-выражения

Лямбда (Java 8) — компактная запись анонимной функции для функциональных интерфейсов (см. [[#Функциональные интерфейсы|функциональные интерфейсы]]).

### Синтаксис и параметры

```java
(параметры) -> выражение
(параметры) -> { тело }
```

```java
// анонимный класс -> лямбда
Runnable r1 = new Runnable() { public void run() { System.out.println("hi"); } };
Runnable r2 = () -> System.out.println("hi");

// параметры
Comparator<String> cmp = (a, b) -> a.compareTo(b);
BiFunction<Integer, Integer, Integer> add = (a, b) -> a + b;
```

Типы параметров можно опускать — компилятор выводит из контекста.

Формы параметров:

```java
() -> 42                 // без параметров
x -> x * x               // один параметр без скобок
(int x, int y) -> x + y  // с явными типами — скобки обязательны
(var x, var y) -> x      // с var (Java 11) — скобки обязательны
```

### Возвращаемые значения

Одиночное выражение возвращается неявно; для блока нужен `return`:

```java
Function<Integer, Integer> square = x -> x * x;        // неявный return
Function<Integer, Integer> squareBlock = x -> { return x * x; };
```

Лямбда-выражение (не блок) не может содержать операторы — только выражение.

### Захват переменных

Лямбда может использовать переменные из внешней области видимости.

### effectively final

Захватывать можно только переменные, которые **не меняются** после инициализации («effectively final»). Изменение — ошибка компиляции:

```java
int base = 10;
Function<Integer, Integer> f = x -> x + base;   // ок

// base = 20;  // ошибка: base больше не effectively final
```

## Функциональные интерфейсы

Интерфейс ровно с одним абстрактным методом.

### `@FunctionalInterface`

Аннотация-проверка: компилятор требует один абстрактный метод (default/static не считаются).

```java
@FunctionalInterface
interface Greeter {
    String greet(String name);
}
```

### `Predicate`

`T -> boolean` — проверка условия:

```java
Predicate<String> nonEmpty = s -> !s.isEmpty();
nonEmpty.test("x");   // true
```

### `Function`

`T -> R` — преобразование:

```java
Function<String, Integer> len = String::length;
len.apply("abc");   // 3
```

### `Consumer`

`T -> void` — потребление значения:

```java
Consumer<String> print = System.out::println;
```

### `Supplier`

`() -> T` — поставка значения:

```java
Supplier<Double> rand = Math::random;
rand.get();
```

### `UnaryOperator` и `BinaryOperator`

Частные случаи `Function`/`BiFunction` с одинаковыми типами:

```java
UnaryOperator<String> upper = String::toUpperCase;
BinaryOperator<Integer> max = Math::max;
```

### Композиция функциональных интерфейсов

У `Function`, `Predicate`, `Consumer` есть default-методы для цепочек:

```java
Function<Integer, Integer> inc = x -> x + 1;
Function<Integer, Integer> dbl = x -> x * 2;

inc.andThen(dbl).apply(3)   // 8  — сначала inc, потом dbl (dbl(inc(3)))
inc.compose(dbl).apply(3)   // 7  — сначала dbl, потом inc

Predicate<String> nonEmpty = s -> !s.isEmpty();
Predicate<String> longEnough = s -> s.length() > 3;
nonEmpty.and(longEnough).test("abc")   // true
nonEmpty.negate().test("")             // true
```

### `BiFunction` и `BiConsumer`

Двухаргументные варианты:

```java
BiFunction<String, String, String> join = (a, b) -> a + b;
BiConsumer<String, Integer> printKV = (k, v) -> System.out.println(k + "=" + v);
```

## Ссылки на методы

Сокращённая запись лямбды, если тело — вызов существующего метода.

### Статические методы

```java
Function<String, Integer> len = String::length;   // вместо s -> s.length()
```

### Методы экземпляра

```java
Consumer<String> print = System.out::println;     // s -> System.out.println(s)
```

### Методы произвольного объекта

```java
Function<String, String> upper = String::toUpperCase;  // s -> s.toUpperCase()
```

### Конструкторы

```java
Supplier<List<String>> factory = ArrayList::new;  // () -> new ArrayList<>()
```

## Stream API

Stream (Java 8) — декларативная обработка последовательностей данных: фильтрация, преобразование, агрегация. Не хранит данные — вычисляет лениво.

### Создание Stream

```java
Stream.of("a", "b", "c");
list.stream();              // из коллекции
Arrays.stream(new int[]{1, 2});  // из массива
IntStream.range(0, 10);
Stream.iterate(0, n -> n + 1);          // бесконечный
Stream.generate(Math::random);          // бесконечный
Stream.ofNullable(obj);                 // пустой или из одного элемента
```

```java
// из файла (Java 11+)
Files.lines(Path.of("data.txt")).forEach(System.out::println);
```

Ограниченная версия `iterate` (Java 9) с предикатом остановки:

```java
Stream.iterate(0, n -> n < 10, n -> n + 1)   // 0..9
```

Пустой поток и concat:

```java
Stream.empty();
Stream.concat(streamA, streamB);   // склейка двух потоков
```

### Pipeline

Цепочка: источник → промежуточные операции (lazy) → завершающая операция (терминальная).

```java
List<String> result = list.stream()
        .filter(s -> s.length() > 2)   // промежуточная
        .map(String::toUpperCase)       // промежуточная
        .toList();                      // завершающая
```

### Ленивость (lazy evaluation)

Промежуточные операции не выполняются, пока не вызвана терминальная. Поток — **одноразовый**: после завершения его нельзя переиспользовать.

```java
Stream<String> s = list.stream().filter(x -> {   // filter не выполняется
    System.out.println("проверка " + x);
    return true;
});
// вывод не появится, пока нет терминальной операции
s.count();   // только теперь выполнится фильтр
```

### Intermediate operations

Ленивые: не выполняются, пока не вызвана терминальная. Возвращают новый stream.

### Terminal operations

Запускают вычисление и завершают pipeline.

## Промежуточные операции

### `filter`

Оставляет элементы по предикату:

```java
list.stream().filter(n -> n % 2 == 0)
```

### `map` и `flatMap`

`map` — один вход → один выход. `flatMap` — один вход → несколько (разворачивает вложенные потоки):

```java
List<List<Integer>> grid = List.of(List.of(1, 2), List.of(3));
grid.stream().flatMap(List::stream)   // 1, 2, 3

// flatMap с Optional
list.stream().flatMap(Optional::stream)
```

### `sorted`

```java
list.stream().sorted();                          // естественный порядок
list.stream().sorted(Comparator.reverseOrder());
```

### `limit`, `skip`, `distinct`

```java
stream.limit(5);       // первые 5
stream.skip(3);        // пропустить 3
stream.distinct();     // уникальные
```

### `peek`, `takeWhile`, `dropWhile`

```java
stream.peek(System.out::println);   // побочное действие (для отладки)
stream.takeWhile(n -> n < 5);       // брать, пока условие истинно
stream.dropWhile(n -> n < 5);       // отбросить, пока истинно
```

`takeWhile`/`dropWhile` (Java 9) работают только с упорядоченными потоками.

## Завершающие операции

### `forEach`, `count`, `min`, `max`

```java
stream.forEach(System.out::println);
long n = stream.count();
OptionalInt min = IntStream.of(3, 1, 2).min();
Optional<Integer> max = list.stream().max(Comparator.naturalOrder());
```

### `toArray`

```java
Object[] objs = stream.toArray();                    // Object[]
String[] arr = stream.toArray(String[]::new);        // типизированный массив
```

### `findFirst`, `findAny`

```java
Optional<String> first = list.stream().findFirst();
Optional<String> any = list.stream().findAny();   // для parallel
```

### `anyMatch`, `allMatch`, `noneMatch`

```java
list.stream().anyMatch(n -> n > 0);    // есть ли положительное
list.stream().allMatch(n -> n > 0);    // все положительные
list.stream().noneMatch(n -> n < 0);   // нет отрицательных
```

## `reduce`

Свёртка потока в одно значение:

```java
int sum = IntStream.of(1, 2, 3, 4).reduce(0, Integer::sum);  // 10
Optional<String> concat = list.stream().reduce((a, b) -> a + b);
```

Формы:

- `reduce(identity, accumulator)` — с начальным значением, результат не `Optional`.
- `reduce(accumulator)` — без начального значения, `Optional` (пустой поток → пустой `Optional`).

Типовой паттерн «map-reduce»:

```java
double total = items.stream()
        .mapToDouble(Item::price)
        .reduce(0.0, Double::sum);
```

Для параллельных потоков есть вариант с дополнительным комбинатором (см. [[#Parallel streams|parallel]]): `reduce(identity, accumulator, combiner)`.

## `collect` и Collectors

Гибкий сбор результатов в изменяемые контейнеры.

### `toList`, `toSet`, `toMap`

```java
List<String> l = stream.collect(Collectors.toList());
Set<String> s = stream.collect(Collectors.toSet());
Map<String, Integer> m = stream.collect(Collectors.toMap(
        Item::name, Item::price));
```

С Java 16 короткая `stream.toList()` (неизменяемый список).

`toMap` с обработкой конфликта ключей (дубликаты):

```java
Map<String, Item> byName = items.stream().collect(Collectors.toMap(
        Item::name,
        Function.identity(),
        (a, b) -> b));            // при дубликате — последний
```

### `joining`

Склейка строк:

```java
String csv = list.stream().collect(Collectors.joining(", "));
String withBraces = list.stream().collect(Collectors.joining(", ", "[", "]"));
```

### `groupingBy`, `partitioningBy`, `mapping`

```java
Map<String, List<Item>> byCategory =
        items.stream().collect(Collectors.groupingBy(Item::category));

Map<Boolean, List<Item>> cheap =
        items.stream().collect(Collectors.partitioningBy(i -> i.price() < 100));

Map<String, List<String>> namesByCat = items.stream().collect(
        Collectors.groupingBy(Item::category,
                Collectors.mapping(Item::name, Collectors.toList())));

// группировка с агрегацией
Map<String, Long> countByCat = items.stream().collect(
        Collectors.groupingBy(Item::category, Collectors.counting()));
Map<String, Double> avgByCat = items.stream().collect(
        Collectors.groupingBy(Item::category,
                Collectors.averagingDouble(Item::price)));
```

`partitioningBy` — частный случай группировки по `Boolean` на две группы.

### Агрегирующие коллекторы

```java
Collectors.counting();
Collectors.summingInt(Item::price);
Collectors.averagingDouble(Item::price);
Collectors.maxBy(Comparator.naturalOrder());
Collectors.summarizingDouble(Item::price);   // count, sum, min, average, max
```

## Примитивные потоки

`IntStream`, `LongStream`, `DoubleStream` — потоки примитивов без автоупаковки.

### `IntStream`, `LongStream`, `DoubleStream`

```java
int sum = IntStream.rangeClosed(1, 100).sum();       // 5050
IntStream.of(3, 1, 2).average();                     // OptionalDouble
DoubleStream.of(1.5, 2.5).map(d -> d * 2);
```

### `boxed` и агрегаты

```java
IntStream stream = IntStream.range(0, 10);
Stream<Integer> boxed = stream.boxed();   // в Stream<Integer>

IntSummaryStatistics stats = IntStream.range(1, 10)
        .summaryStatistics();   // count, sum, min, average, max
```

## Parallel streams

### Когда использовать

Параллельный режим — при большом объёме данных и дорогих операциях; выигрыш не гарантирован.

```java
long total = list.parallelStream()
        .mapToLong(this::expensive)
        .sum();
```

### Ограничения

- Накладные расходы на распараллеливание; малые потоки — медленнее.
- Порядок обработки не гарантирован.
- Использует общий пул потоков (`ForkJoinPool.commonPool`) — см. [[14. Многопоточность и конкурентность#Executors|Executors]].
- Результат может зависеть от порядка обработки: операции, чувствительные к порядку (`findFirst`, `limit`), в параллельном режиме дороже или ведут себя иначе.

### Побочные эффекты

Операции должны быть чистыми (без состояния и общего мутируемого состояния). Не использовать разделяемые коллекции без синхронизации:

```java
// плохо: гонки в общем списке
List<Integer> bad = new ArrayList<>();
list.parallelStream().forEach(bad::add);

// хорошо: собрать через collect
List<Integer> good = list.parallelStream().collect(Collectors.toList());
```

### Атомарность и корректность

Лямбды обязаны быть **без состояния** и **ассоциативными**:

```java
// некорректно: счётчик с общим состоянием
AtomicInteger wrongCount = new AtomicInteger();
list.parallelStream().forEach(x -> wrongCount.incrementAndGet());

// корректно: reduce с ассоциативной операцией
int count = list.parallelStream().reduce(0, (acc, x) -> acc + 1, Integer::sum);
```

## mapMulti

`mapMulti` (Java 16+) — альтернатива `flatMap` для случаев, когда нужно более эффективно порождать элементы из stream:

```java
// flatMap: создаёт список и разворачивает
Stream<String> flat = list.stream().flatMap(s -> List.of(s, s.toUpperCase()).stream());

// mapMulti: то же, но без создания промежуточного списка
Stream<String> multi = list.stream().mapMulti((s, consumer) -> {
    consumer.accept(s);
    consumer.accept(s.toUpperCase());
});
```

`mapMulti` эффективнее `flatMap`, когда число порождаемых элементов мало и фиксировано — не создаёт промежуточный объект для каждого элемента.

## teeing (Java 12+)

`Collectors.teeing` — объединение двух коллекторов в один:

```java
record Stats(long count, double sum) { }

Stats stats = items.stream().collect(
    Collectors.teeing(
        Collectors.counting(),
        Collectors.summingDouble(Item::price),
        Stats::new
    )
);
// Stats[count=3, sum=150.0]
```

Полезен, когда нужно одновременно вычислить две агрегации по одному потоку.

## Gatherers (Java 22+)

`Stream.gather(Gatherer)` — preview в Java 22, стабильный в Java 24+. Пользовательские промежуточные операции, расширяющие встроенные `filter`/`map`/`flatMap`:

```java
// встроенные gatherer'ы
Stream.of(1, 2, 3, 4, 5)
    .gather(Gatherers.windowFixed(2))  // [[1,2], [3,4], [5]]
    .toList();

// скользящее окно
Stream.of(1, 2, 3, 4)
    .gather(Gatherers.windowSliding(3)) // [[1,2,3], [2,3,4]]
    .toList();

// параллельная обработка с упорядочиванием
Stream.of(1, 2, 3)
    .gather(Gatherers.mapConcurrent(2, x -> x * 2))
    .toList();  // [2, 4, 6]
```

Gatherers заменяют ручные коллекторы для сложных промежуточных операций.
